# DeepCASE 訓練標記不足實驗

本實驗檢查攻擊標記稀少時，加入輔助訓練目標與平衡抽樣，能否在不增加送審量下提高攻擊召回。AIT-ADS 的攻擊事件並不稀少，實驗只隱藏部分訓練標記，保留原始事件流及驗證、測試分布。

## 最終結果

主要設定為已揭露攻擊：正常＝1:1000，使用六個測試情境、三個初始化種子。在相近送審量下，送審召回平均提高 0.59 個百分點，95% 信賴區間為 −0.39 至 +1.64 個百分點，包含零，尚不足以認定有提升。

主要實驗直接使用模型注意力，記為 `q=0`。100 次注意力查詢的 `q=100` 次要檢查只有 17/18 組配對可行，可用配對的描述性平均召回差為 −0.84 個百分點，不計算正式信賴區間或 p 值。

送審召回同時計入自動判為攻擊及 Reject 後送審的真實攻擊。送審率是自動升級與 Reject 占全部事件的比例，未實測分析員工時。完整判讀見[最終報告摘要](../../docs/final_report_summary.md)。

## 方法與比較條件

- `deepcase` 為下一事件預測基準，`proposed` 在實際送入 Interpreter 的脈絡表示上加入攻擊輔助目標與平衡抽樣。
- 輔助目標僅用於訓練，部署時由共同的 Interpreter 輸出攻擊、正常或 Reject。
- `fox` 與 `russellmitchell` 用於方法設計，另外六個完整情境用於確認測試。
- 配對共用切分、揭露標記、種子、訓練預算及修正索引對應後的 Interpreter。
- 脈絡只用嚴格較早事件，所有學習統計只由訓練情境建立。

## 重現所需條件

由 [AIT-ADS 官方資料頁](https://doi.org/10.5281/zenodo.8263181)下載作者提供的告警 CSV，依 `config.yaml` 放入資料目錄。套件版本見專案根目錄的 `requirements.txt`。資料、模型與產生的結果檔未隨專案提供。

公開目錄已整理為 `experiments/imbalance/`，但 `run.ps1` 仍以其上一層作為專案根目錄，未對應目前結構。完整重跑前須先核對執行工作目錄、共用資料位置及結果輸出位置。分析修正後的實驗時，使用 `aligned_v2` 結果命名空間，避免混入修正前的紀錄。

技術報告中的 `research_experiments/` 是整理前的目錄名稱，歷史產物路徑也不代表檔案已包含在此版本中。
